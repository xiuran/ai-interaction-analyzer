你每天都在和 AI 工具对话——编码、排查、写文档、做方案，这些对话日志躺在本地硬盘上，从来没人看过。

这个工具帮你看。它扫描你本地 AI 工具的对话记录（支持 **Claude Code / Codex / Qoder / Cursor**），找出 AI 反复犯错的模式和你一次就搞定的模式，然后产出 **可以直接复制到任何 AI 工具配置文件里的规则**。

不是统计报告，是可执行的规则。

**--- 6. AI 协作指南（核心产出，给 AI 读） ---**

报告产出一段可直接安装到 CLAUDE.md / AGENTS.md / .cursorrules 的协作指南。以下是示例：

```
## AI 协作指南（auto-generated by ai-interaction-analyzer, 2026-07-02）

### 关于这个用户
- 习惯直接下指令，很少给背景——你需要自己读代码和文档补上下文
- 对"编造"零容忍——不确定的 API/字段/路径，必须先验证再写入代码
- 期望增量迭代——收到反馈时只改反馈点，已经确认过的内容不动
- 同时推进多个项目，经常跨仓库工作——注意确认当前操作的目标仓库

### 判断原则

| 原则 | 判断标准 | 适用场景 |
|------|---------|---------|
| 先查后写 | 调用不熟悉的 API 前必须 Read 源码确认签名 | 二方/三方包调用 |
| 最小改动 | 收到修改意见后只改那一条，用 diff 而非全量覆盖 | 迭代打磨 |
| 验证再说 | 断言代码结构前先用 grep/find 搜索确认 | 排查、Code Review |
| 看完整体 | 新增配置/枚举时，先看已有实现注册了哪些文件 | 多模块项目 |

### 行为规则
1. 调用不熟悉的 API 时，必须先 Read 源码确认方法签名和返回值类型，禁止凭记忆写
2. 新增枚举/配置时，先看同类已有实现注册了几个文件，然后逐个同步
3. 收到修改意见时，先列"要改的点"和"不动的部分"，确认后用 Edit 精准替换
4. 排查问题时，先列"已确认事实"和"待验证假设"，信息不足不给确定性结论
5. 代码变更后做全局检查：删除废弃 import/注释/常量，统一魔法值为枚举
6. 前端修改后必须验证视觉效果，无法截图时显式声明"需要人工验证"
```

**--- 7. Prompt Rules ---**

从根因模式中抽象出的通用规则，适用于任何人、任何项目。可直接复制安装：

```
1. 调用不熟悉的 API 前，先 Read 源码确认方法签名和返回值类型。禁止凭记忆猜测。
2. 参照已有实现做新功能时，先 Read 完整方法体理解逻辑，不能只看签名就套模板。
3. 排查问题时，信息不足禁止给确定性结论。先列"已确认"和"待验证"两个清单。
4. 收到修改意见后只改被指出的点，用精准替换而非全量覆盖。禁止连带重写。
5. 代码变更后全局检查：删除废弃注释/import/常量，统一使用枚举替代散落的魔法值。
6. 新增枚举/错误码/配置时，先看同类已有实现注册了几个文件，逐个同步注册。
7. 前端代码修改后必须验证视觉效果。无法截图时显式说明"样式需要人工验证"。
8. 组织代码/文档结构时，先确认业务域归属，按业务边界而非技术模块划分。
```

> 每条规则溯源到具体的根因模式和 incident 数量。完整报告中展示溯源链。
> 规则分两层：**通用规则**（从行为模式抽象，任何开发者适用）和**定制发现**（仅对当前用户有价值，标注可选）。

```
  Skill / 工作流驱动     → 封装好的流程，成功率 >90%
  单次精准指令           → 边界清晰，不涉及架构决策

▎翻车区（注意）
  多仓/跨模块编码        → 首轮指定涉及的仓库和关键文件
  长 session（30+ 轮）   → 目标漂移 + 上下文丢失，拆成多个 session
  线上排查               → 给具体报错 + 可疑文件路径，减少 AI 猜测

▎可操作改进
  - [Rules] 安装上面的 AI 协作指南到 CLAUDE.md / AGENTS.md
  - [Hooks] 前端文件修改后强制截图验证（PostToolUse hook）
  - [模型] 复杂任务用更强模型（问题率可降 40-60%）
  - [上下文] 编码任务首条 prompt 附带设计文档路径和涉及的文件清单
  - [习惯] AI 连续 2 轮没做对时重写 prompt，不追加碎片指令
```

```
                  │ 发现问题 incident
```

## 安装

### 最快的方式

```bash
git clone https://github.com/xiuran/ai-interaction-analyzer ~/.claude/skills/ai-interaction-analyzer
```

然后在 Claude Code 对话里输入 `/ai-trace`，AI 会自动跑完整分析。

### 独立 CLI

```bash
git clone https://github.com/xiuran/ai-interaction-analyzer
cd ai-interaction-analyzer

python3 scripts/analyzer.py --mode=scope             # 看看有哪些数据源
python3 scripts/analyzer.py --mode=analyze            # 跑完整分析（默认 60 天）
python3 scripts/analyzer.py --mode=analyze --days=90  # 指定分析最近 90 天
python3 scripts/analyzer.py --mode=analyze --days=30  # 只看最近一个月
python3 scripts/analyzer.py --mode=signals --days=15  # 只扫信号（更快）
```

**时间范围**：默认分析最近 60 天（自动调节：>3000 条缩到 30 天，<300 条扩到半年）。不传 `--days` 参数则分析全部历史数据。

CLI 输出原始 JSON 数据。完整的格式化报告（仪表盘 + 根因分析 + 规则）需要通过 AI 执行 — 在 Claude Code 里输入 `/ai-trace`，AI 会读取 SKILL.md 指令，调用脚本采集数据，按模板输出格式化报告。

## 规则安装

分析完成后，规则可以直接安装到你使用的 AI 工具中。两种方式：

**方式 1：让 AI 自动写入**（在 Claude Code 中对 AI 说"把规则写入 CLAUDE.md"即可）

**方式 2：手动复制**（报告末尾有纯文本版规则，直接复制到对应文件）

| 工具 | 项目级 | 全局级（跨项目生效） |
|------|--------|---------------------|
| Claude Code | 项目根目录 `CLAUDE.md` | `~/.claude/CLAUDE.md` |
| Codex | 项目根目录 `AGENTS.md` | `~/.codex/AGENTS.md` |
| Cursor | `.cursor/rules/*.mdc` 或 `.cursorrules` | Settings → General → Rules for AI |
| Cline | `.clinerules/` 目录 | `~/Documents/Cline/Rules/`（macOS）|
| Windsurf | `.windsurf/rules/*.md` 或 `.windsurfrules` | Settings → AI Rules（`global_rules.md`）|
| 其他工具 | — | 工具设置中的 System Prompt / Custom Instructions |

规则分两层：**通用规则**（适用于任何人、任何项目）和 **个性化发现**（只对你有价值，标注可选）。
