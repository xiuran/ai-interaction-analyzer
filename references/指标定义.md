# 指标定义与公式

## 1. Prompt 信息完整度

衡量 prompt 在形式上给了 AI 多少可直接开工的信息，不判断 prompt 好坏。
分档用中性描述：信息充分（80-100）/ 基本够用（60-79）/ 偏简（40-59）/ 极简（0-39）。

### 公式

单条 prompt 评分 = 长度 + 引用 + 目标 + 上下文 + 聚焦

| 维度 | 满分 | 标准 |
|------|------|------|
| 适当长度 | 20 | 50-500 字符 = 20，20-50 = 10，500+ = 15 |
| 具体引用 | 25 | 包含文件路径或 `file:line` 格式 |
| 明确目标 | 20 | 包含目标动词（实现/修复/添加/删除等） |
| 提供上下文 | 20 | 包含原因/背景关键词（因为/目前/之前等） |
| 目标聚焦 | 15 | 1-2 个目标动词 = 15，3+ = 5 |

总分 = mean(所有真实 prompt 的评分)，上限 100。

### 排除项

- 斜杠命令（`/xxx`）不参与质量评分
- 纯数字或单个符号不参与评分

### 欠信息率

欠信息 prompt = 长度 > 10 字符，但没有文件引用且没有目标动词。
欠信息率 = 欠信息 prompt 数 / 总真实 prompt 数 × 100%

## 2. 对话效率评分

### 公式

效率 = 一次成功率 × 40% + (1 - 否定率) × 30% + 工具密度 × 30%

| 组成 | 权重 | 定义 |
|------|------|------|
| 一次成功率 | 40% | ≤ 3 轮且无否定的 session / 总 session |
| 无否定率 | 30% | 没有否定词的 session / 总 session |
| 工具密度 | 30% | min(tool_events / prompts, 2) / 2 |

### 否定关键词

中文：`不对` `不是` `重来` `重做` `改一下` `错了` `换一个` `换一种` `别这样` `不要这样` `不要这么` `不要这个` `重新`

英文：`wrong` `incorrect` `undo` `revert` `redo` `not right` `start over` `go back` `that's not`

### 轮次分级

| 分级 | 范围 | 说明 |
|------|------|------|
| 快速 | 1-3 | 一次搞定或简单确认 |
| 中等 | 4-10 | 正常复杂度任务 |
| 深度 | 11-30 | 复杂任务或探索性对话 |
| 马拉松 | 30+ | 注意 session 膨胀风险 |

## 3. 沟通模式

### 协作风格分类

| 风格 | 触发词 | 描述 |
|------|--------|------|
| 委托式 | 帮我 / 去做 / 给我 / 直接做 | 完全委托给 AI |
| 协作式 | 我们 / 一起 / 想想 / 讨论 / 你觉得 | 双方共同思考 |
| 审查式 | 检查 / review / 看看 / 审一下 | 用户主导，AI 验证 |
| 指令式 | （其他） | 明确指令，无协作信号 |

### 任务类型分类

| 类型 | 关键词匹配 |
|------|-----------|
| 编码 | 写代码 / 实现 / 开发 / function / method / class / interface / import / def |
| 调试 | bug / error / 报错 / 异常 / 不工作 / fix / debug / trace |
| 调研 | 搜索 / 调查 / 查一下 / 对比 / 评估 / 怎么做 / 是什么 |
| 写作 | 写文章 / 文档 / 总结 / 报告 / 博客 / README |
| 配置 | 配置 / 安装 / 部署 / 环境 / hook / settings / config |

---

## 4. 反模式检测规则

| 反模式 | 触发条件 | 严重度 |
|--------|---------|--------|
| 重复否定 | 同一 session 中 ≥ 2 个连续否定词 prompt | 🔴 高 |
| 过短命令 | 同一 session 中 ≥ 3 个 < 10 字符的非命令 prompt | 🟡 中 |
| Session 膨胀 | 单个 session > 50 轮 | 🟢 低 |
| 目标漂移 | 同一 session 中任务类型切换 ≥ 3 次 | 🟡 中 |

### 排除项

- 斜杠命令不算"过短命令"
- 编码 session 天然轮次多，50+ 阈值仅供参考
- 目标漂移检测基于连续类型变化（相邻同类型合并）

## 5. AI 行为质量指标（规划中 — 需要 tool_use 事件解析）

以下指标需要从 session JSONL 中提取 AI 的 tool_use 事件才能计算。

### 5.1 Read:Edit 比

```
Read:Edit ratio = Read 调用数 / Edit 调用数
```

| 范围 | 评价 |
|------|------|
| ≥ 2.0 | 优秀：AI 充分阅读后再修改 |
| 1.5 - 2.0 | 良好 |
| 1.0 - 1.5 | 一般：可能存在"不读就写"风险 |
| < 1.0 | 危险：AI 改得比读的还多 |

### 5.2 不读就写比率

```
不读就写比率 = 没有 Read 前序的 Edit 数 / 总 Edit 数 × 100%
```

定义"没有 Read 前序"：对某个文件的 Edit 调用，在其之前 5 个 tool_use 事件内没有对同一文件的 Read 调用。

| 范围 | 评价 |
|------|------|
| 0-10% | 优秀 |
| 10-30% | 一般 |
| > 30% | 高风险：大量修改没有先阅读 |

### 5.3 工具密度

```
工具密度 = min(tool_use 事件数 / prompt 数, 2) / 2
```

用于效率评分公式中。工具密度越高，说明 AI 每次收到 prompt 后执行了更多实际操作。

### 数据源

- Claude Code: session JSONL 中 `type: "tool_use"` 的记录，`name` 字段为工具名（Read/Edit/Write/Bash 等）
- Codex: rollout JSONL 中 tool call 记录
- Qoder: transcript JSONL 中 tool 调用记录
